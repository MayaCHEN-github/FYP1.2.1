# 会话层

证据状态：除特别标注外，本页基于当前源码已确认。

## 白话模型

会话层维护「某个模型 + 某条系统提示」下的消息历史，并在每次用户输入后把完整历史交给模型层流式生成回复。Gradio 演示里会为两个模型各开一条独立会话，因此同一条攻击提示会并行得到两份回答。

会话 ID 由模型名、系统提示键和序号拼接，格式形如 `gpt-4_system_message0_0`。

## 代码模型

入口类：[`ConversationManager`](../../chains/conversation_chain.py)。

| 方法 | 行为 |
| --- | --- |
| `initialize_conversation(model_name, system_message_key)` | 创建 ID，历史首条为 system 消息 |
| `get_streaming_response(conversation_id, user_input)` | 追加 user 消息 → 调 `ModelManager.get_streaming_response` → 流式 yield token → 结束后追加 assistant 完整文本 |
| `get_conversation_history(conversation_id)` | 跳过 system，把 user/assistant 转成 `(user, assistant)` 元组列表 |

注意：`get_streaming_response` 从 `conversation_id` 用 `split('_')[0]` 取模型名，因此模型别名本身不能含下划线（当前别名均满足）。

[`app.py`](../../app.py) 的 `generate_responses` 不经过多轮对话，仅单轮 user → assistant；历史结构仍按 Chat 格式保留，便于扩展。
